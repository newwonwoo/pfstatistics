## 2. 원인 분석

카카오 타일(`*.daumcdn.net`)에는 CORS 헤더가 없다(실측). `html-to-image` 는 DOM 을
SVG `foreignObject` 로 감싸 캔버스에 그리는 방식이라, 타일 인라인에 실패하면
**전체가 빈 그림**이 되고 실패 사유도 남지 않는다. 타일 `src` 를 `/api/tile` 로
바꿔치기하는 우회를 넣어도 결국 같은 `foreignObject` 경로를 타서 불안정했다.

## 3. 설계 — 베끼지 말고 다시 그린다

좌표(중심·반경·마커·경계)는 앱이 이미 갖고 있다. DOM 을 베낄 이유가 없다.

1. 타일 — 화면에 깔린 이미지를 DOM 순서(=쌓임 순서)대로 모아 같은 출처(`/api/tile`)로
   다시 받아 캔버스에 그대로 찍는다. `<img>` 와 CSS `background-image` 양쪽을 본다.
2. 오버레이 — `Projection.containerPointFromCoords` 로 픽셀을 구해 반경원·사업지 경계·
   마커·라벨을 캔버스에 직접 그린다. 반경 픽셀은 **정북 radius m 지점을 투영해** 재므로
   축척 가정이 없다. 마커도 카카오 기본 마커 이미지 대신 직접 그려 CORS 대상이 남지 않는다.
3. 각주 — 캡쳐만 떼어놔도 알아볼 수 있게 제목·반경·판정기준·일시를 하단에 새긴다.

## 4. 검증

### 4-1. 합성기 (실제 브라우저 · Chromium)

카카오 SDK 는 도메인 제한이 걸려 있어 샌드박스 브라우저에서 못 띄운다.
그래서 **카카오 지도와 같은 모양의 DOM**(타일 `<img>` 6 + `background-image` 1,
`Projection` 대역)을 만들어 합성기를 그대로 돌리고, 결과 PNG 의 **픽셀을 읽어** 확인했다.

| 확인 항목 | 기대 | 실측 |
|---|---|---|
| 타일 탐지 | 7 (img 6 + 배경 1) | `타일 7 · img 6` |
| 결과 크기 | 600×400 ×2배 | 1200×800 |
| 타일 합성 | `#2e7d32` | `46,125,50` |
| 반경원 선 | `#FFEB3B` | `255,235,59` |
| 반경원 채움 | 타일색 + 보라 18% | `74,129,80` |
| 사업지 경계 선 | `#1b4fd8` | `27,79,216` |
| 시설 마커 | `#EA4335` | `236,86,73` |
| 사업지 마커 | `#1b4fd8` | `50,96,219` |

| 각주 띠 | 흰 반투명 | `238,245,239` |

## 5. 곁들여 고친 결함

- **RadiusMap 이 지도를 두 번 만들고 있었다.** `markers` 가 렌더마다 새 배열이라
  `useEffect` 의존성이 매번 바뀌어, `setReady(true)` 후 재렌더에서 같은 div 에 지도가
  한 번 더 생성됐다. 내용 비교(JSON)로 바꾸고 재생성 시 컨테이너를 비운다.
- **사업지 경계가 반경원 지도에 안 보였다.** 판정은 경계 기준인데 증빙에는 그 경계가
  없으면 "왜 이 거리인가" 를 설명할 수 없다. 화면·캡쳐 양쪽에 그린다.
- **실패해도 조용했다.** 합성이 안 되면 예전 방식으로 한 번 더 시도하고, 그래도 안 되면
  타일 개수까지 넣은 사유를 지도 아래에 띄운다.

## 6. 남는 한계

- 실사이트 브라우저 확인은 못 했다. 이 샌드박스는 브라우저의 외부 HTTPS 터널이 끊기고
  (`ERR_CONNECTION_RESET`), 카카오 JS 키는 `pfstatistics.vercel.app` 로 도메인 제한이라
  localhost 에서도 SDK 를 못 띄운다. **카카오 DOM 구조 자체는 사용자 화면에서 확인이 필요하다.**
  실패하면 지도 아래에 `타일 N · img N · 요소 N` 형태의 사유가 뜨므로 그 값으로 바로 잡을 수 있다.
- 라벨이 지도 위쪽 끝에 걸리면 잘릴 수 있다(화면과 동일한 동작).
