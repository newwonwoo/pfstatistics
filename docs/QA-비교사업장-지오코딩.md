## 2. 분석

지오코딩 실패를 **세어보는 것**부터 했다(`/api/apts?...&census=1`).
경기 고유주소 945건 중 45건 실패, 그 45건이 **전부 지구·블록 표기**였다.
카카오 장소검색에 `부동산 > 부지 > 개발지구` 카테고리가 있어
"성남낙생 공공주택지구 @경기 성남시 분당구 동원동 산 47-13" 로 **지번까지** 나온다 — 요구2의 답.

## 3. 설계

- 지오코딩 단계에 `zone` 을 넣는다 : `exact → name → **zone** → dong → place`
- **일반명사로는 묻지 않는다.** 고유명이 든 질의만 쓰고 결과 이름을 대조한 뒤 채택한다
- 좌표를 얻으면 반경 판정에 넣고, 근사라는 사실을 봉투·배지·지도 핀 이름에 실어 끝까지 들고 간다
- 못 찾은 것은 **건수 한 줄**(요구3), 단계별 잔량은 표 위 **깔때기 한 줄**(요구1)

## 6. 발견·수정한 결함

| # | 결함 | 영향 |
|---|---|---|
| 1 | 일반명사 질의가 엉뚱한 지구를 잡음 (시흥장현→시흥은계) | 틀린 좌표가 조용히 반경 판정에 들어감 |
| 2 | `sggOfWords` 가 "장항지구" 를 시군구로 읽음 | 멀쩡한 매칭을 버림 |
| 3 | `headOf` 가 "양주회천신도시" 를 시군구로 읽음 | 질의가 중복되어 0건 |
| 4 | `ZONE_TAIL` 이 읍면동을 앞에서부터 삼킴 | 근사 좌표·개편 대조 둘 다 불가 |
| 5 | 행정구역 개편으로 시군구 대조가 전부 거부 | 인천 실패 17건 중 15건 |
| 6 | 지번 칸 placeholder 가 골든 표본 주소 | 입력한 값과 구분 안 됨 (기록된 함정의 재발) |
