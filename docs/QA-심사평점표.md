# 품질확인서 — 심사평점표 (최종 산출물)

- 대상 : 실제 심사평점표(탄벌A지구) 캡쳐 · 평가기준 설명표 · 초기분양률 배점표 (2026-09-16 수령)
- 커밋 : `9bdd92e`
- 검증자 : 자가검증 (골든 평점표 재현 + 구간 경계 전수 + 연동규칙 조합 전수)

## 1. 드러난 구조

```
시트별 항목 점수 → 종합평가 점수 → 초기예상분양률(%) → 초기분양률 배점(22점)
                                                     → 종합평점 → 심사등급 → 보증료율
```

이 앱이 만들던 모든 것이 **심사평점표의 초기분양률(22점) 한 칸**으로 수렴한다.

## 2. 요구사항 적합 여부

| # | 요구사항 | 결과 |
|---|---|---|
| 1 | 초기분양률 배점표 적용 | **적합** — 골든 70% → 16점 일치 |
| 2 | 초기예상분양률 자동 연결 | **적합** — 두 탭이 같은 함수(`expectedRateOf`) 사용 |
| 3 | 사업성은 수동입력 | **적합** — 사용자 결정대로 입력칸, 아는 구간은 근거로 표기 |
| 4 | 0점 처리 규칙 | **적합** — 자동 적용 + 배지·배너로 근거 표시 |
| 5 | 미수령 구간표 추정 금지 | **적합** — 심사등급·보증료율은 빗금 유지 |

## 3. 초기분양률 배점 — 경계 전수

```
100% → 22점  (100%)                 99% → 21점  (90% 이상 ~ 100% 미만)
 90% → 21점                         89% → 19점  (80% 이상 ~ 90% 미만)
 80% → 19점                         79% → 16점  (70% 이상 ~ 80% 미만)
 70% → 16점  ← 골든                 69% → 13점  (60% 이상 ~ 70% 미만)
 60% → 13점                         59% → 10점  (50% 이상 ~ 60% 미만)
 50% → 10점                         49% →  0점  (50% 미만)
```
100% 는 단독 구간(22점)이고 99% 부터 21점이다 — 원문이 "100%" 와 "90%이상-100%미만" 으로 나뉜다.

## 4. 골든 평점표 재현 (탄벌A지구)

| 구분 | 평가항목 | 배점 | 평점 |
|---|---|---|---|
| 사업수지분석 (65) | 사업수익률 (10.64%) | 20 | 20 |
| | **초기분양률 (70%)** | **22** | **16** ← 자동 |
| | 누적DSCR분석값 (1.05) | 3 | 3 |
| | 자기자금 투입규모의 적정성 (4.51%) | 20 | 20 |
| 시공자 사업수행능력 (35) | 시공능력평가액순위 (17위) | 15 | 15 |
| | 신용평가등급 (AAA) | 15 | 15 |
| | 자기자본대비 PF보증 잔액 비율 (45.6%) | 5 | 5 |
| | **합계** | **100** | **94** |

초기분양률만 이 앱이 자동으로 냈고 나머지는 캡쳐의 강조값을 넣었다.
합계 94점은 확인된 등급 구간(86점 이상 = 1등급 · 보증료율 0.563%)에 든다.

## 5. 0점 처리 규칙 — 조합 전수

> 초기분양률이 50% 미만이거나 누적DSCR분석값이 1.00 미만인 경우,
> 초기분양률 및 누적DSCR 항목 평점을 모두 0점 처리함

```
분양률 49% · DSCR 1.05  →  초기분양률 0 · DSCR 0  →  합계 75   [0점 처리]
분양률 70% · DSCR 0.99  →  초기분양률 0 · DSCR 0  →  합계 75   [0점 처리]
분양률 49% · DSCR 0.99  →  초기분양률 0 · DSCR 0  →  합계 75   [0점 처리]
분양률 70% · DSCR 1.05  →  초기분양률 16 · DSCR 3 →  합계 94
```
어느 한쪽만 걸려도 **두 항목이 같이** 0점이 된다. 94 → 75 로 19점이 빠지는 큰 규칙이라
자동으로 걸되 `0점 처리` 배지와 배너로 **왜 0인지** 반드시 남긴다.

누적DSCR은 점수 칸과 **별도로 실측값 입력칸**을 둔다 — 점수(3점)만으로는 1.00 미만인지 알 수 없다.

## 6. 배점 판독 — 두 캡쳐가 달랐다

| | 실제 평점표 캡쳐 | 설명표 캡쳐 |
|---|---|---|
| 시공능력평가액순위 | 15 | 5 |
| 신용평가등급 | 15 | 15 |
| 자기자본대비 PF보증잔액비율 | 5 | 10 |
| 합 | 35 | 30 |

실제 평점표는 **합계 100 · 사업수지분석 65** 를 명시하므로 시공자 쪽은 35 여야 한다
(65 + 35 = 100, 15+15+5 = 35 로 두 번 맞는다). 설명표 캡쳐는 흐려서 다르게 읽혔을 가능성이 높다.
**합계가 맞는 쪽을 따랐고**, 이 사실을 config `_note` 와 화면 각주에 남겼다.
실제 평점표의 그룹 라벨이 `(30)` 으로 읽혔으나 항목 합·총계와 맞지 않아 **쓰지 않고 항목 합으로 낸다.**

## 7. 미수령 (빗금 유지)

- **종합평점 → 심사등급 → 보증료율** 구간표 — 캡쳐가 `86점이상 / 1등급 / 0.563%` 한 줄에서 잘렸다
- 각 항목의 **하위 구간** — 최고점 행만 보인다
  (13.5%↑=20 · 1.05↑=3 · 8%↑=20 · 1~20위=15 · AAA/AA=15 · 50%미만=5)
  → 수동입력으로 두고 아는 구간을 근거 칸에 적어 실무자가 대조할 수 있게 했다

## 8. 결론

요구사항에 **적합**하다. 골든 평점표를 재현했고(합계 94), 배점 경계 13개와
0점 처리 조합 4개를 전수 확인했다. 추정으로 채운 구간은 없다.
