# 품질확인서 — 화면 동선 (눈·마우스·클릭·실시간 반영)

- 요구사항 : "직접 화면을 보고 UIUX 수정할 부분 발굴해서 수정하자. 스스로 만족스러울 때까지.
  **눈동자의 이동 최소화 / 마우스 포인터 이동 최소화 / 클릭수 최적화(최소화 아님) /
  과잉 실시간 반영에 따른 혼란초래 UX**"
- 대상 : 배포본 https://pfstatistics.vercel.app/
- 커밋 : 시작 `317966f` → `eed2022` → `108c857` → `f448eb0` → `0c6b3b5` → **`5cb67cd`**
- 방법 : 헤드리스 브라우저로 **1440×900(실무자 노트북)** 에서 실제로 조작하고
  **스크롤 0 화면**을 매 단계 캡쳐해 눈으로 확인 → 고침 → 다시 몰아봄 (4회 반복)
- 표본 : 경기도 광주시 탄벌동 203-4 / 제일건설(주)
- 검증자 : 자가검증

## 1. 가장 컸던 것 — 끝난 단계가 화면을 먹고 있었다

심사평점표 탭인데 **화면 900px 중 830px 이 이미 끝난 단계**였다.

```
제목 · 리드문 · 원천 배지 · STEP 줄 · 입력폼 · 사업지 매칭 · 단계 버튼 줄
· 경계 지도 · 저장된 조회 · 통계 수치카드   ← 여기까지 830px
──────────────────────────────────────────  ← 그제서야 값을 넣을 표
```

입력칸과 그 결과(종합평점·보증료율)가 **한 화면에 없으니** 눈도 마우스도 왕복한다.

고친 방식은 하나다 — **그 단계의 도구는 그 단계에서만 편다.**

| 무엇 | 언제 보이게 했나 |
|---|---|
| 입력 그리드 (시도·시군구·지번·조회월·시공사) | 주소 확정 전까지. 확정되면 **한 줄 요약**으로 접고 [사업지 바꾸기] 로 편다 |
| 단계 버튼 줄 | 자료수집 단계 탭에서만 |
| 사업지 경계 지도 | **경계로 재겠다고 정했을 때만** (전에는 주소 확정 직후부터 350px) |
| 저장된 조회 | 보관본이 있을 때만 |
| 통계 수치카드 · 원천 상태 배지 | 자료수집 단계 탭에서만 |
| 안내 리드문 | 주소 확정 전까지 |
| [이 조회 보관] · [엑셀 다운로드] | 항상 — **사업지 요약 줄 오른쪽에 붙여** 한 줄을 아꼈다 |

접힌 자리에는 "무엇을 심사 중인가" 한 줄만 남는다. 그건 어느 단계에서나 필요하다.

```
경기도 광주시 탄벌동 203-4   202607 · 제일건설(주) · 통계 7/7 · 시설 3/3 · 비교사업장
                                   [이 조회 보관] [엑셀 다운로드] [사업지 바꾸기]
```

**실측 — 심사평점표 표 첫 행의 y좌표**

```
317966f  830px      (표가 화면 밖. 스크롤해야 입력칸이 나온다)
eed2022  660px
5cb67cd  480px      ← 7개 항목 중 5개가 값·평점·근거까지 한 화면에
```

## 2. 과잉 실시간 반영 — 합계가 "16 / 100" 으로 읽혔다

사업수익률 한 칸(10.64)만 넣었는데 **합계 칸에 16 이 떴다.** 배점 100 바로 옆이라
낮은 평점처럼 읽히는데, 실제로는 7개 중 1개만 평가한 값이다.

| | 전 | 후 |
|---|---|---|
| 합계 칸 | `16` (배점 100 옆) | `1 / 7` (진행도) |
| 근거 칸 | 수동입력 6개 남음 | 값을 넣은 항목 1개 · 남은 항목 6개<br>전 항목을 넣어야 합계가 납니다 *(지금까지 넣은 것만 더하면 16점)* |

**숫자를 없앤 것이 아니라 총점으로 오독되지 않게 자리를 옮겼다.**
진행 중 확인은 여전히 되고, 배점 옆에서 총점 행세를 하지 못한다.

사슬의 나머지는 이미 막혀 있었고 그대로 두었다 —
종합평점·심사등급·보증료율은 전 항목이 차야 나오고(`net = missing.length ? null : …`),
A 는 12항목이 다 차야 확정되며, 초기예상분양률은 A 와 분양가경쟁력이 둘 다 있어야 난다.

## 3. 클릭수 **최적화** (최소화가 아니다)

파란 버튼이 셋이면 다음에 뭘 누를지 셋이 동시에 주장한다.
교통환경·주거편의·교육환경을 **어차피 다 눌러야** 하고 기준까지 물으면 4클릭이었다.

- 한 번에 받는 길은 이미 있었다(`runPoi(null)`) → **[반경시설 수집 (3종)] 하나**로 묶었다 (4클릭 → 2클릭)
- **개별 재수집은 없애지 않았다.** 다 끝난 뒤에만 `✓교통환경 ✓주거편의 ✓교육환경` 으로
  보조 표시된다 — 하나만 다시 받고 싶을 때가 있다. 이것이 "최소화가 아닌 최적화" 다.

막힌 자리에서는 **그 자리로 보내는 버튼**을 뒀다 (전에는 "[수기입력] 탭에서 하세요" 글씨뿐이라
위로 스크롤해 탭을 찾아야 했다).

- 초기예상분양률 ① A → `[수기입력 탭으로 →]` · ② 분양가경쟁력 → `[비교사업장 탭으로 →]`
- 심사평점표 초기분양률 행 → `[초기예상분양률 탭으로 →]`

## 4. 마우스 포인터 이동

| 자리 | 전 | 후 |
|---|---|---|
| [주소 확정] | x=157 — 마지막 입력칸(시공사 x=1105)에서 **950px 되돌아감** | **x=1195** (한 줄을 통째로 쓰고 오른쪽 끝) |
| 수기입력 결과 | 입력칸 **아래** 점선 밑 (세로 이동) | 입력칸 **옆** — 세로차 **2px** |

※ 결과를 처음엔 `marginLeft:'auto'` 로 오른쪽 끝에 붙였는데 입력칸(x=182)과 1000px 떨어졌다 —
아래로 움직이던 눈이 옆으로 멀리 움직이게 됐을 뿐이라 **바로 옆(x=581)** 으로 당겼다.

| # | 증상 | 원인 |

| 1 | 심사평점표 값 칸 placeholder 가 전부 **「점수」** | 이 칸이 받는 것은 원시값(1.05 · 4.51% · 17위)이다. `reviewScore` 가 `band` 를 판정 라벨로 **덮어쓰며 구간표의 단위를 지웠고**, 화면이 못 찾아 기본값으로 떨어졌다 → `% · 값 · % · 위 · %` |

## 6. 요구사항 적합 여부

| # | 요구사항 | 결과 |

| 2 | 눈동자 이동 최소화 | **적합** — 평점표 표 y 830 → **480px**, 입력↔결과 세로차 **2px** |

| 5 | 과잉 실시간 반영 제거 | **적합** — 부분합 `16` → 진행도 `1 / 7`, 부분합은 근거 칸 괄호로 |
| 6 | 콘솔 오류 | **적합** — 0건 |

## 7. 남긴 것 (일부러)

- **STEP 줄은 뒤 단계에서도 남긴다.** 어디까지 왔는지는 어느 단계에서나 필요하다.
- **부분합 숫자를 지우지 않았다.** 진행 중 확인은 필요하다 — 총점 자리에서만 뺐다.
- **개별 시설 재수집 버튼을 없애지 않았다.** 클릭을 줄이는 것이 목적이 아니다.
- 비교사업장 탭에서도 통계 수치카드가 보인다. "자료수집 단계" 라는 한 규칙으로 묶었고,
  더 잘게 나누면 규칙이 복잡해져 어디서 무엇이 보이는지 예측이 어려워진다.
