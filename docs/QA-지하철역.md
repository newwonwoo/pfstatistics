# 품질확인서 — 지하철역 평가점수

- 일자 : 2026-09-14
- 배포 : `ca7083a` (`/api/config` 의 `commit` 으로 확인)
- 대상 : 교통환경 시트 「지하철역」 행의 점수·평가 칸

## 1. 분석 — 무엇이 확정돼 있고 무엇이 없는가

사용자가 준 구간표 캡쳐 2장을 다시 폈다.

| 캡쳐 | 담긴 표 |
|---|---|
| 1장 | 교육환경 (5/4/3/2/1) |
| 2장 | 상업시설 및 의료시설 (7/5/4/3/1) + 공원·문화·공공시설 (3/2/1) |

**두 캡쳐 어디에도 지하철역 표는 없다.** 2장 캡쳐의 맨 아랫줄에 다음 표의 첫 행이
잘려 들어와 있으나(점수 5), 글자 윗부분만 남아 판독되지 않는다.
사용자 회신: **"내일 제대로 줄게"**.

대신 **골든 캡쳐**(`docs/evidence-samples/01_교통환경.jpg`)에 한 행이 확정돼 있다.

```
지하철역 | (시설명 없음) | 사업지 반경 1km이내 부재 | 1점
```

## 2. 설계 — 확인된 만큼만 적용한다

- 부재행은 골든으로 확정 → `base = 1점 · 매우열악`, 문구도 캡쳐 그대로.
- 역이 반경 안에 있을 때의 구간은 미수령 → `pending: true`.
  **점수를 비우고 사유만 적는다.** 추정으로 채우면 아래 구간이 대신 걸려
  틀린 점수가 조용히 매겨진다(주거편의에서 같은 함정을 이미 겪었다).
- 구간표는 `config/scoring.json` 한 곳에만 둔다. 내일 표를 받으면
  **JSON 에 행 몇 줄을 더 얹는 것으로 끝난다 — 코드는 손대지 않는다.**

## 3. 개발

| 파일 | 변경 |
|---|---|
| `config/scoring.json` | `지하철역` (scope `poi`) 추가. `base` 에 골든 출처(`verified`) 명기 |
| `src/lib/scoring.js` | `scorePoi()` — 시설 하나의 존재 여부로 판정 |
| `app/SheetView.js` | flat 레이아웃에서 비수기 항목도 채점. `pending` 이면 점수칸 빗금 + 사유 |
| `app/exportExcel.js` | 엑셀도 같은 규칙 (점수 공란, 사유 문구) |

## 4. 검증

### 4-1. 단위 (`scorePoi`)

| 입력 | 결과 |
|---|---|
| 1km 내 0건 | `1점 · 매우열악` / "사업지 반경 1km이내 부재" |
| 900m 에 1건 | `pending` / "사업지 반경 1km이내 존재 — 구간표 미수령" |
| 1,200m 에 1건 | `1점 · 매우열악` (반경 밖이므로 부재) |
| 수집 전 | `null` (빗금 유지) |

### 4-2. 화면 (로컬 Chromium, **실제 수집결과**를 보관함에 주입해 재현)

수집값: `/api/facilities?addr=경기도 광주시 탄벌동 203-4&sheet=교통환경` → **지하철역 0건**

```
["지하철역","사업지 반경 1km 이내","부재","-","1","1점 · 매우열악 (사업지 반경 1km이내 부재)"]
```

→ 골든 캡쳐의 「사업지 반경 1km이내 부재 / 1」 과 **일치**.

같은 화면에 820m 역(경기광주역)을 넣었을 때:

```
["지하철역","사업지 반경 1km 이내","경기광주역","820m","","사업지 반경 1km이내 존재 — 구간표 미수령"]
```

→ 점수칸이 비어(빗금) 있고 사유가 보인다. **틀린 점수가 매겨지지 않는다.**

## 5. 요구사항 적합 여부

| 요구 | 판정 |
|---|---|
| 지하철역 평가점수를 매긴다 | **부분 충족** — 부재(1점)는 골든과 일치. 존재 구간은 표 미수령으로 보류 |
| 추정해서 채우지 않는다 | 충족 |
| 미수령 구간이 눈에 보인다 | 충족 (화면·엑셀 모두 사유 표기) |
| 표를 받으면 바로 적용된다 | 충족 (`config/scoring.json` 행 추가만) |
