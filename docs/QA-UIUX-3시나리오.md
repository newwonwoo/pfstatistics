- 일자 : 2026-09-24
- 배포 : `5f5fc51`(점검) → `57af4c6` · `02f3205` · `8d0481a`(수정 후 재시험)
- 방법 : 배포본을 헤드리스 브라우저로 **사람처럼 끝까지 조작**하고,
  단계마다 **화면에 보이는 버튼을 전수 기록**했다(라벨 · 비활성 · 주버튼 여부 · 좌표).
  사업성 값은 사슬을 끝까지 돌리기 위한 **가상 입력**이다(실제 심사 결과가 아니다).

## 찾은 문제와 수정

### 1. 파란색이 세 가지 뜻으로 겹쳤다 — 주버튼이 한 화면에 넷

비교사업장 탭 한 화면에서 `[1km]` `[공급면적]` `[세대수 가중]`(**고른 상태**)과
`[반경 1km 분양단지 수집]`(**실행**)이 똑같은 진한 파랑이었다.
"지금 뭘 눌러야 하나" 가 넷으로 갈렸다.

→ **고른 상태는 옅게(accentSoft + 밑줄), 실행만 진하게.**
실측 주버튼 수 : 비교사업장 탭 **4 → 1**, 본건 제원 입력 후 **4 → 0**.

### 2. 끝난 일이 끝난 것처럼 보이지 않았다

- **탭 옆 완료 점이 앞 8개 탭에만** 있었다. 정작 실무자가 값을 넣는
  비교사업장 · 수기입력 · 초기예상분양률 · 심사평점표에는 아무 표시가 없었다 —
  그 넷은 탭 줄 오른쪽 끝이라 스크롤 밖일 때가 많아 더 안 보인다.
  → 넷 모두 상태를 낸다. `ok`(결론까지 났다) / `partial`(손댔지만 결론 없음).
- `[반경 N km 분양단지 수집]` 이 수집 뒤에도 그대로라 **또 눌러야 하는 줄 알았다.**
  단계 줄의 다른 버튼은 끝나면 ✓ 초록으로 바뀌는데 이것만 안 바뀌었다.
  → `✓ 반경 3km 수집됨 — 다시 수집` 으로 문법을 맞췄다.
- 이미 비교사업장 탭에 있는데 단계 줄 `[비교사업장 · 분양가 →]` 가
  **화면 맨 위에서 계속 파란 "다음"** 이라 주장했다. → 그 탭에 있으면 주버튼을 뗀다.

### 3. 막다른 길 — 0건일 때 다음 행동이 없었다

반경 1km 에 비교단지가 0곳이면 표에는 **본건만** 남는데 화면은
「아래 표에서 비교사업장을 고르세요」 라고만 했다. 고를 것이 없는데 고르라는 셈이다.
세 시나리오 **모두** 규정 기본 반경에서 0곳이었다(부천·여주·평택).

→ 0곳일 때만, 규정 제16조 **비고1** 문구(「인근에 유사사업장이 없는 경우 반경을 매 1km
확대하여 적용」)와 `[반경 2km 로 넓히기]` 버튼을 **그 자리에** 둔다.
반경 줄은 이 자리에서 한참 위라 찾아 올라가야 했다.
(0곳이 아닐 때는 권유하지 않는다 — 몇 곳으로 평균을 낼지는 실무자가 판단한다)

### 4. 조건이 걸렸는데 화면이 말하지 않았다

「100세대 미만이면 60% 상한이 걸립니다」 가 **1,859세대에도 99세대에도 같은 문장**이었다.
C(99세대)는 상한 대상인데 그 사실을 알 길이 없었다.

→ 해당하면 「100세대 미만 — **60% 상한 적용 대상**」 으로 바꿔 적고,
상한이 실제로 값을 내렸으면 `(70% → 60%)` 를, 급간 값이 이미 60% 이하면
`(급간 값이 이미 60% 이하라 변동 없음)` 을 같이 적는다.

### 5. 같은 글자의 버튼이 한 시트에 두 쌍

교통환경 시트에 지도 확대·축소 `[＋][－]` 와 차선 증감 `[＋][−]` 가 **같은 글자**로 있었다.
점검 스크립트가 **지도만 여섯 번 확대하고 차선은 0 인 채** 넘어갔다 — 사람도 같은 실수를 한다.
게다가 6차선을 넣으려면 `＋` 를 **여섯 번** 눌러야 했다.

→ 차선은 `[2][4][6][8]` 칩으로 **한 번에** 고르고, 스테퍼는 `▲▼` 로 글자를 갈랐다.
실측: 클릭 6회 → **1회**. 재시험에서 「송내대로 (왕복 6차선) · 0m · 5점 · 매우양호」로 들어간다.

### 6. 넣는 버튼이 넣는 칸에서 280px 떨어져 있었다

심사평점표의 `[7위 넣기]` 가 **근거 칸**에 있었다. 값 칸은 왼쪽이다.
같은 성격의 버튼이 비교사업장 탭에서는 입력칸 바로 옆이라 **문법도 갈렸다.**
→ 값 칸 안, 입력칸 바로 아래로 옮겼다. 설명은 근거 칸에 그대로 남긴다.

### 7. 일반구가 있는 시에서 기축 단지 보강이 통째로 죽었다

K-apt 와 실거래가 색인은 **구 단위**인데(원미 41192 · 소사 41194 · 오정 41196),
단지 주소 앞 **두 토막**만 떼어 「경기 부천시」(41190)로 물어 **0건** →
세대수 · 시공사 · 사용승인일 · 실거래 단가가 **전부 빈 표**가 그려졌다.
그러고는 화면이 그것을 「K-apt 에서 **이름이 맞지 않은 것**」 이라고 설명했다 — **틀린 이유**다.
수원 · 성남 · 안양 · 안산 · 고양 · 용인 · 창원 등 일반구가 있는 시가 전부 같은 증상이다.

→ 구가 있으면 세 토막을 쓴다(「지구」도 「구」로 끝나므로 막았다 — 기록된 함정).
실측: 색인 시군구가 「경기 부천시 원미구」 로 잡히고 **실거래 단가가 채워진다**
(5,749,928 · 4,091,456 · 6,421,460 원/㎡).
K-apt 는 별개로 원천이 들쭉날쭉해 색인이 0건일 때가 있어, **색인을 못 받은 것과
이름이 안 맞은 것을 구분해** 적도록 고쳤다.

### 8. 게이트웨이 오류가 개발자 메시지로 노출

비교사업장 수집 중 화면에 그대로 떴다 —
`Unexpected token 'u', "upstream r"... is not valid JSON`.
실무자에게 아무 뜻도 없고 무엇을 해야 하는지도 말하지 않는다.

→ JSON 읽기를 `app/fetchJson.js` **한 곳**으로 모으고,
본문이 JSON 이 아니면 「원천에 닿지 못했습니다 (502) — 잠시 뒤 다시 시도하세요」 로 바꾼다.

### 9. 접힌 손잡이가 지금 상태를 말하지 않았다

[반경시설 수집] 을 눌러 **이미 그리기 모드에 들어온 뒤에도** 경계 지도 손잡이가
「경계 미지정 — **[반경시설 수집] 을 누르면** 여기서 그립니다」 그대로였다.
이미 누른 사람에게 "버튼을 또 누르라" 고 읽힌다 — 실제로 할 일은 지도를 찍는 것이다.

→ 상태별로 갈라 적는다. 실측(커밋 `8d0481a`) :
```
수집 전     : 경계 미지정 — [반경시설 수집] 을 누르면 여기서 그립니다
그리기 모드 : 지도를 클릭해 경계를 찍으세요 — 0점 (3점부터 경계가 됩니다)
3점 이상    : 경계 4점 지정됨 — 경계 기준으로 잽니다
```

## 중복 트리거 점검 결과

같은 기능이 여러 자리에 흩어져 있는지 전수로 봤다. **정리할 것은 6번 하나였다.**

| 겹쳐 보이는 것 | 판정 |
|---|---|
| `[이 조회 보관]`·`[엑셀 다운로드]` 가 요약 줄과 단계 줄에 각각 | **문제 아님** — `panelOpen` 으로 갈려 **동시에 보이지 않는다**(입력폼을 편 상태 / 접은 상태) |
| 비교사업장 `[50위 이내]` 와 심사평점표 `[7위 넣기]` | **다른 항목이다** — 앞은 유사도 판정용 구간, 뒤는 배점용 순위. 다만 **자리가 달라** 6번으로 맞췄다 |
| 지도 기준 `[경계 기준]/[중심 기준]`(시트) 과 단계 줄 `[변경]` | **다른 일이다** — 앞은 *그리는* 기준, 뒤는 *수집한* 기준. 라벨이 그렇게 말한다 |
| 반경시설 수집이 단계 줄과 경계 지도 발치에 | **의도된 것** — 경계를 고른 그 순간에만 지도 발치에 나타났다 사라진다(기록된 규칙) |

## 재시험 (수정 후)

세 건 모두 처음부터 끝까지 다시 돌렸다.

| | A 부천 상동 | B 여주 홍문동 | C 평택 평택동 |
|---|---|---|---|
| 6차선 도로 | 송내대로 0m · 왕복 6차선 → 5점 | 여양로 0m · 6차선 → 5점 | 평택로 0m · 6차선 → 5점 |
| 종합평가 점수 | 77 | 57 | 50 |
| 초기예상분양률 | 80% | 60% | 50% |
| 초기분양률 배점 | 19 | 13 | **10 → 0** (0점 처리) |
| 종합평점 | 92 | 63.7 | 34 |
| 심사등급 · 요율 | **1등급 0.563%** | **5등급 1.104%** | **보증거절** (60점 미만) |

· C 는 **0점 처리 규칙**(초기분양률 50% 미만 **또는** DSCR 1.00 미만 → 두 항목 모두 0점)이
  실제로 걸려 배너와 배지로 표시된다. **99세대 60% 상한**도 「60% 상한 적용 대상」으로 적힌다.
· 차선 입력이 **클릭 6회 → 1회**로 줄었고, 고치기 전 점검에서 지도만 확대되고 차선이 0이던 것이
  세 건 모두 정상으로 들어간다.
· 비교사업장 탭 **주버튼 4 → 1**(수집 전) · **4 → 0**(본건 제원 입력 후).
· 세 건 모두 규정 기본 반경에서 비교단지 0곳이었고, 새로 넣은 비고1 안내와
  `[반경 넓히기]` 로 그 자리에서 넓혀 진행했다.

**B 는 1회차에 지도가 뜨지 않아 경계를 못 찍고 시설 수집이 비었다.**
앱 문제가 아니라 이 샌드박스 프록시의 간헐 502 다(기록된 증상) — 다시 돌려 정상 통과했다.
다만 그 실패 덕에 9번(손잡이 문구)을 찾았다.

## 판정

**요구사항 적합.** 3건 시나리오가 주소확정부터 보증료율까지 끊기지 않고 흐르고,
버튼의 활성·비활성·완료 표시가 단계와 맞는다.
찾은 문제 9건을 모두 고쳐 같은 시나리오로 재확인했다.

사업성 값(사업수익률·자기자금·신용등급·DSCR·PF보증잔액)은 **가상 입력**이다 —
이 앱이 수집하지 않는 항목이므로 사슬 점검용으로만 넣었다.

## 덧 — 관문 (2026-09-24, 커밋 `1252fee`)

「비어 있는 항목이 있으면 심사평점표로 못 넘어가게」 라는 지적에서 출발했다.
확인해 보니 **비어 있는 것은 이미 막혀 있었다** — A 가 null 이면 종합평가도 합계도 등급도 안 난다.
새고 있던 것은 **비어 있지 않은데 판정을 안 한 쪽**이었다.

**6차선 차선 수와 인구유입요인은 안 넣으면 비는 게 아니라 기본 1점이 들어간다.**
그래서 A 가 「나와버리고」 보증료율까지 아무 말 없이 갔다.
실측: 시나리오 A 에서 차선 미입력 종합 **75** / 입력 후 **77** — 75 는 「75~85」 급간 경계 바로 위다.

고친 것
· 섞였으면 **초기예상분양률을 심사평점표로 넘기지 않는다** (page.js 한 지점에서 끊는다)
· 초기예상분양률 탭이 그 사실과 사유를 적고 그 탭으로 보낸다
· 심사평점표에 **관문 한 장** — ✗/✓ 목록 + 각 줄에서 그 탭으로 (튕김 3회 → 0회)
· **탭 자체는 막지 않았다** — 사업수익률·자기자금·신용등급은 이 앱이 수집하지 않는 값이라
  사업수지표를 손에 든 실무자가 먼저 넣어둘 수 있어야 한다. 막는 것은 결론이다

단계별 실측 (부천 상동, 커밋 `1252fee`)

| 상태 | 관문 | 결론 |
|---|---|---|
| ① 아무것도 안 함 | 남은 것 **6개** | 합계 0/7 · 등급 — |
| ② 통계 + 시설 | **5개** — 「교통환경 — 판정 전 기본점수 · 6차선 왕복도로 미입력」 이 뜬다 | 등급 — |
| ③ 차선 입력 | **4개** (교통환경 항목이 사라진다) | 등급 — |
| ④ 비교사업장 + 수기입력 3종 | **1개** — 「지역수요 — 인구유입 요인 개수를 넣으세요 (없으면 0)」 | 합계 0/7 · 등급 — |
| ⑤ 전부 | **관문 없음** | 합계 **92** → **1등급 0.563%** |

④ 에서 표의 초기분양률(22) 행은 「위 관문의 남은 항목 1개를 채우면 찹니다」 로 적히고,
사업수익률·DSCR·자기자금·시공순위·신용등급 **입력칸은 열려 있다.**
