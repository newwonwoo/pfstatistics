- 요구사항 : "화면 직접 사용해보고 버그나 UIUX 개선점 발굴해서 수정하고, 수정 후에 재테스트"
- 대상 : 배포본 https://pfstatistics.vercel.app/
- 커밋 : 점검 `57fb021` → 1차 수정 `cace202` → 2차 수정 `369fbe6`
- 방법 : 헤드리스 브라우저(Playwright + Chromium)로 **실제 배포본을 사람처럼 끝까지 조작**
- 표본 : 경기도 광주시 탄벌동 203-4 / 시공사 제일건설(주) (골든 표본)
- 검증자 : 자가검증

## 1. 어떻게 몰아봤나

한 번에 끝까지 간다 — 중간만 보면 화면 사이에서 끊기는 자리를 못 찾는다.

```
주소 확정 → 통계 수집(7/7) → 교통환경·주거편의·교육환경 수집(대표지번 중심 기준)
→ 비교사업장 반경 3km 수집 → 비교단지 3곳 선택 → 본건 예정분양가 6,050,000
→ 수기입력(규모및배치·평형구성·인근초기분양률·점수직접 2개)
→ 초기예상분양률 → 심사평점표(사업성·시공자 값 입력)
→ [이 조회 보관] → 새로고침 → [열기] 로 복원 확인
```

한 바퀴에 약 5분(원천 호출 대기 포함). 매 단계에서 콘솔 오류·HTTP 4xx·전체화면 캡쳐를 남겼다.

### 사슬 전체가 화면에서 돌아가는 것을 처음으로 확인했다

전에는 단위 테스트로만 맞춰봤다. 이번에 **화면에서** 끝까지 이어지는 것을 봤다.

```
A 56  +  분양가경쟁력 6  =  종합평가 62점
      → 급간표 55~65점 미만 → 초기예상분양률 60%
      → 초기분양률 배점 13점
      → 합계 81  − 감점 1  → 종합평점 80  → 2등급  → 보증료율 0.697%
```

같은 입력을 코드에서 직접 돌린 결과와 화면이 일치한다.
골든(탄벌A지구) 조건으로 바꿔 넣으면 84 → 83 → 2등급 0.697% 로 정답지와 같다.

## 5. 추가 — 판정 전 기본점수가 섞인 평균 (2026-09-17, `c7f419e`)

사용자 확인 : **"두개는 개별 판단요소이고 평균점수를 내는거야."**
교통환경(지하철역 · 6차선 왕복도로) · 주거편의(상업·의료 / 문화·공공·공원) 모두
항목마다 따로 판정하고 그 **평균**으로 등급을 낸다. 산식(`scoreAverage`)은 맞게 돌고 있었다.

문제는 **그 평균이 어디까지 따라가느냐**였다. 6차선을 아직 판정하지 않으면 기본 1점이 평균에 섞이고,
`scoreAverage` 가 그 사실을 `caution` 으로 돌려주는데도 **시트와 엑셀에만 적히고 A 합산표부터는 버려졌다.**
A 는 초기예상분양률 → 초기분양률 배점 → 보증료율까지 흘러가므로,
거기서 사라지면 「판정 전 1점」이 「판정 결과 1점」으로 둔갑한다.

| | 교통환경 | 근거 | 초기예상분양률 영향 |
|---|---|---|---|
| 판정 전 | 1점 | 지하철역 1 + 6차선 1 ÷ 2 | 두 급간 낮음 |
| 판정 후 | **3점** | 지하철역 1 + 6차선 **4** ÷ 2 = 2.5 → 보통 | 골든 캡쳐 01 과 동일 |

수정
- `manualSummary` 가 항목별 `caution` 과 `provisional` 목록을 같이 돌려준다
- 수기입력 A 합산표 — 해당 행의 근거와 합계행에 "판정 전 기본점수가 섞여 있습니다"
- 교통환경 시트 — 판정 전 항목의 점수 칸을 **노란 확정색에서 뺀다**(노란 칸은 확정된 값 자리다),
  "판정 전 기본 1점 — 차선 수 미입력" 으로 적는다

기본 1점 규칙 자체는 그대로다(사용자 확정: 기본 1점은 무조건 있다) — **확정처럼 보이지 않게만** 했다.

### 같은 뿌리에서 더 큰 것이 나왔다 (`c5f3431`)

위를 고치며 `manualSummary` 를 단위로 돌려보니, **교통환경만 수집했는데
주거편의·교육환경에도 `1점 · 매우열악` 이 붙어 있었다.**

`distOf` 가 null 을 주는 경우가 둘인데 뜻이 정반대다.

| null 인 이유 | 옳은 처리 | 실제 |
|---|---|---|
| 수집했는데 반경 안에 없다 | 부재 → 구간표 base 1점 | 1점 ✓ |
| **아직 수집하지 않았다** | **아직 모른다 → 점수 없음** | 1점 ✗ |

통계까지 수집하면 A 가 그대로 확정돼 초기예상분양률 · 초기분양률 배점 · 보증료율까지 흘러간다.
판단요소마다 따로 판정해 평균을 내는 구조라, 판정 안 한 항목이 섞이면 평균이 통째로 틀어진다.

- `sheetGathered()` — `page.js` 의 `poiDone()` 과 **같은 기준**(그 시트로 수집된 항목이 하나라도 있는가).
  0건으로 수집된 항목도 봉투는 남으므로 "수집했는데 0건" 은 참이 된다.
- `scorePoi` · `scoreGroup` · `scoreSheet` 가 수집 전이면 `pending` 을 돌려준다
- `scoreAverage` 의 pending 문구는 사유가 하나뿐이면 그 사유를 그대로 쓴다

검증 (단위)

```
교통환경만 수집 → 주거편의 · 교육환경
                 "반경시설을 아직 수집하지 않았습니다 — [… 수집] 을 누르세요"
3종 전부 수집 + 도로 판정 → 교통환경 3 · 주거편의 3 · 교육환경 2 · provisional 0
```
